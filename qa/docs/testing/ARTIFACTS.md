# Артефакты прогонов LLM-сервиса

Где лежат результаты генерации и как их читать.

## Где

```text
services/school_events_llm/data/runs/<job_id>/
services/school_events_llm/data/runs/runs.jsonl
```

`data/` не коммитится в git: артефакты локальные. Для команды их нужно приложить файлом или отрендерить в markdown.

Готовые markdown-версии 18 сценариев лежат локально в `qa/docs/review/generated/` и в git не коммитятся.

## Что внутри

| Файл | Что это |
|---|---|
| `input.json` | Исходный запрос |
| `normalized_request.json` | Запрос после нормализации |
| `concepts.json` | План вариантов |
| `metadata.json` | Модель, статус, время, токены, вызовы, ошибки |
| `final_result.json` | Итоговый ответ по контракту 02 |
| `variants/v1/variant_package.json` | Сценарий до рендера |
| `variants/v1/validation.json` | Замечания валидатора |
| `calls/call_XXXX/` | `prompt.md`, `messages.json`, `response.raw.txt`, `response.parsed.json`, `manifest.json` |
| `events.jsonl` | Трасса: этапы, повторы, исправления |
| `runs.jsonl` | Журнал всех прогонов: статус, время, токены, замечания |

## Как прочитать сценарий

```bash
cd services/school_events_llm
python -m app render data/runs/<job_id>/variants/v1/variant_package.json \
  --request data/runs/<job_id>/input.json --markdown
```

## Как оценивать

1. **Статус и время** — `metadata.json`: `status`, `duration_ms`, `llm_calls`, `tokens`.
2. **Замечания** — `validation.json` и `quality_report`: `critical`, `warning`, коды.
3. **Тайминг** — сумма блоков равна запросу, старт с 0, внутри блока хватает времени на действия.
4. **Участники** — число учеников, групп, педагогов, родителей; роли и блоки.
5. **Материалы** — есть ли печать, зависимости, содержание.
6. **Возраст** — лексика, объём, сложность, уместность.
7. **Факты и регион** — даты, имена, источники, `FACT-UNREGISTERED`.
8. **Культура** — стереотипы, навязывание, нейтральность.
9. **Реализуемость** — успевает ли педагог, хватает ли переходов.
10. **Трасса** — были ли повторы и исправления (`events.jsonl`, `calls/`).

## Пример: `labour_day`, 10 класс, 60 минут

`job_953464af28db49eebb1718329a38bf7f`

- 6 блоков, сумма 60, старт с 0.
- 25 учеников, 5 групп по 5, 4 родителя-жюри.
- Материалы: карточки ролей, карточки профессий, бланки проектов, лист жюри, сертификаты.
- `quality_report=warning`: `FACT-UNREGISTERED` — в сертификате стоит «2023 год».
- В задачах заявлено «знакомство с историей праздника», но отдельного исторического блока нет.
- Блок 40–55 минут: 5 команд × до 3 минут = 15 минут, без запаса на переходы и консультацию жюри.

Вывод: структура сильная, содержание уместно для 10 класса, но есть фактическая ошибка в сертификате и тесный тайминг. На демо в таком виде не брать.

## Про скорость

Смотреть `duration_ms` в `metadata.json` или `runs.jsonl`, а не время в терминале: терминал включает запуск, загрузку и вывод.

На прогоне 28.10:

- 18 кейсов, 71–162 секунды на кейс;
- 8–11 вызовов модели на сценарий;
- 19–35 тысяч токенов;
- один кейс 3,9 секунды — ответ провайдера из кэша.

1,5–5 минут в терминале — тот же порядок. Разница зависит от длительности, детализации, числа вариантов, повторов и нагрузки провайдера. Корректно сравнивать только одинаковый запрос.
