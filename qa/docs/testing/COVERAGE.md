# Покрытие тестами

Документ отвечает на вопрос: «12 E2E-кейсов — это много или мало?»

## Уровни проверки

| Уровень | Что проверяет | Сколько |
|---|---|---|
| Юнит-тесты QA | Структура, тайминг, возрастные эвристики | 28 |
| Тесты LLM-сервиса | Генерация, валидаторы, prompt, повторы | 139 + 770 подтестов |
| Интеграция Backend ↔ LLM | Контракты 01/02, ошибки, `partial` | 60 |
| E2E по API | 18 сценариев на 14 событиях | 18 |
| UI-проверка | Путь пользователя, ошибки, `partial`, варианты | ручная |

Итого **199 python-тестов** + 18 E2E-сценариев + UI-прогон.

## Что покрыто E2E

| Измерение | Покрытие |
|---|---|
| События каталога | **14 из 14** |
| Возрастные группы | 1–4, 5–8, 9–11 |
| Форматы | `class_hour`, `school_event`, `interactive_lesson` |
| Длительности | 30, 45, 60, 90 минут |
| Родители | выключены и включены |
| Роли родителей | `helper`, `audience`, `evaluator` |
| Ресурсы | полный набор и минимальный (`projector=false`, `printer=false`) |
| Ошибки | 422 `EVENT_NOT_FOUND`, 422 `CONFLICTING_CONSTRAINTS`, 503 `MODEL_UNAVAILABLE` |
| Статусы | `completed`, `failed`, `partial` |

## Чего нет

| Пробел | Почему важно |
|---|---|
| Все комбинации параметров | 14 событий × 3 возраста × 3 формата × 4 длительности × родители — слишком много; нужен pairwise-набор |
| Систематическая проверка 2–3 вариантов | Сейчас 1 вариант в E2E, многовариантность проверялась точечно |
| UI-сценарии с ролями родителей | Форма не умеет `helper`/`evaluator` (BUG-08) |
| Долгое ожидание и таймаут UI | Проверялось вручную на `partial` |
| Нагрузка и стабильность | Один прогон, без 10–20 повторов |
| Исторические и региональные факты | 0 `verified`-фрагментов, проверка только по чек-листу |
| Автоматизация UI-регрессии | `completed`/`failed`/`partial` проверяются руками |

## Вывод

**12 кейсов — это нормальный smoke-набор для Sprint 2**, но не полное покрытие приложения. После добавления шести событий набор вырос до **18 кейсов** и покрывает все 14 событий каталога.

Для демо и приёмки Sprint 2 этого достаточно. Для релиза нужно:

1. добавить pairwise-матрицу событий, форматов и возрастов;
2. автоматизировать UI-регрессию трёх статусов;
3. проверить многовариантность системно;
4. добавить проверку долгого ожидания и недоступности сервиса;
5. закрыть факты и регион через `verified`-источники.
