## P1

### BUG-01. Фронтенд не обрабатывает `partial` и уходит в таймаут

- **Владелец:** Оля (фронтенд)
- **Где:** `frontend/src/api.ts`, `createProject` (строки 20–26).
- **Шаги:** запросить 3 варианта, дождаться статуса `partial`.
- **Факт:** Backend отдаёт `job.status=partial`, `project.status=partial`, `completed_variants=1`, готовый вариант доступен. Фронтенд ждёт только `completed`, крутит цикл 90 × 1,2 с и через ~108 секунд показывает «Превышено время ожидания генерации».
- **Ожидаемо:** показать готовые варианты и предупреждение, что часть вариантов не готова (ТЗ 16.6, критерии приёмки, раздел 2).
- **Влияние:** пользователь не получает готовый сценарий и видит ложную ошибку.
- **Статус:** исправлено в PR #8 (`fix/llm-frontend-integration`): фронтенд принимает `partial` с готовыми вариантами и показывает предупреждение. Нужен merge и проверка на живой модели.

### BUG-02. `failed` и `partial` не объясняют причину

- **Владелец:** Андрей (LLM-сервис, контракт 02)
- **Где:** `services/school_events_llm/app/http_api.py` (`finish_generation`), `app/generation/pipeline.py` (`VariantOutcome`), контракт 02.
- **Шаги:** отправить запрос, который не проходит проверку плана; сравнить HTTP-ответ и CLI.
- **Факт:** через HTTP `job.errors=[]`, в `project.variants` нет ни одного варианта и нет причины. CLI на том же запросе показывает: `failed / План не прошёл проверку / critical:PLAN-PUPILS:roles, critical:PARENTS-DISABLED:roles`.
- **Ожидаемо:** причина отказа и список issue доступны в `job` или в проекте для каждого варианта (ТЗ 16.2, контракт 02).
- **Влияние:** фронтенд не может показать, что именно не так; поддержка и QA диагностируют только по логам и CLI.
- **Статус:** API-часть исправлена в PR #8: `job.errors` содержит коды и сообщения, статусы вариантов привязаны к `variant_id`. На `partial` интерфейс причины отклонённых вариантов пока не выводит — это отдельная задача из PR.

### BUG-03. Внутренняя арифметика блока не проверяется

- **Владелец:** Андрей (валидатор и текст сценария), проверка — Максим
- **Где:** сценарий `qa/docs/review/scenarios/labour_day_andrey.md`; автоматические проверки тайминга (`check_grid`, `TIMING-*`).
- **Факт:** блок 15–30 мин (15 мин) содержит 10 минут подготовки команд **и** выступления; блок 45–55 мин (10 мин) требует представить 5 команд по «максимум 3 минуты», то есть до 15 минут; блок 30–45 мин начинается словами «После завершения выступлений команд», хотя в нём же запланирована работа на 10 минут. Сумма блоков ровно 60, поэтому автоматика пропускает сценарий.
- **Ожидаемо:** автоматическая проверка бюджета действий внутри блока либо обязательное замечание уровня `high`.
- **Влияние:** педагог физически не успевает провести сценарий.

### BUG-08. Форма не позволяет выбрать роли родителей и режим участия

- **Владелец:** Оля (фронтенд, форма)
- **Где:** `frontend/src/App.tsx`, блок «Участники и пространство».
- **Факт:** есть только чекбокс «В мероприятии участвуют родители» и количество. Форма всегда отправляет `parent_roles=['audience']` и не отправляет `parent_audience_engagement`. Выбрать `helper`, `active_participant`, `evaluator`, голосование или награду нельзя.
- **Ожидаемо:** роли и режим участия доступны в форме, как в контракте 01 (ТЗ 6.2–6.4).
- **Влияние:** через UI нельзя воспроизвести E2E-01, E2E-04, E2E-06 и E2E-12; сценарии с помощниками, жюри и голосованием недоступны пользователю.

### BUG-09. Нет памятки для родителей при включённых родителях

- **Владелец:** Андрей (генерация и проверки)
- **Где:** E2E-12, `womens_day`, 12 родителей, `audience_award`; `quality_report` → `PARENT-INSTRUCTION`.
- **Факт:** на живой модели в сценарии с родителями-помощниками и зрителями нет памятки для родителей, хотя роли и голосование есть.
- **Ожидаемо:** при `parents_enabled=true` и ролях `helper`/`audience` в материалах есть памятка с обязанностями и границами участия.
- **Влияние:** родители приходят без инструкции; педагогу приходится объяснять всё самому.
- **Примечание:** автоматика это поймала как `warning`, выдача не заблокирована.

## P3

### BUG-04. Fixture-режим по HTTP выбирает эталон не по событию

- **Владелец:** Андрей (LLM-сервис, fixture)
- **Где:** `services/school_events_llm/app/llm/fixture.py`, `_golden()`.
- **Факт:** `mothers_day` и `labour_day` через HTTP завершаются `failed`, хотя CLI с соответствующим эталоном завершает их как `completed`. HTTP-клиент берёт эталон по порядку, а не по `event_id`.
- **Ожидаемо:** эталон выбирается по событию запроса.
- **Обход:** `LLM_SERVICE_FIXTURES=<один golden>` под нужное событие.
- **Влияние:** только тестовая инфраструктура. С появлением реальной модели не блокирует E2E и демо.

### BUG-05. `SCRIPT-SHORT`: порог требует калибровки

- **Владелец:** Андрей (порог), решение — Ярослав
- **Где:** `script_length.py`, `checks.py`.
- **Факт:** на fixture-прогонах было по 2 замечания в каждом сценарии (например, 489 символов при пороге 600). На живой модели 28.10 — **0 замечаний из 12 кейсов**.
- **Ожидаемо:** либо оставить порог как есть, либо снизить для коротких блоков, чтобы не ловить ложные срабатывания.
- **Влияние:** на живых прогонах не воспроизводится; риск остаётся для коротких блоков и краткой детализации.

### BUG-07. Демо-каталог фронтенда расходится с реальным

- **Владелец:** Оля (фронтенд, демо)
- **Где:** `frontend/src/api.ts`, `DEMO_EVENTS`.
- **Факт:** в демо 2 события и `teacher_day`, в реальном каталоге 14 событий и `teachers_day`.
- **Ожидаемо:** демо использует реальный каталог или явно помечен как учебный.
- **Влияние:** только демо-режим.

### BUG-10. `job.warnings` не доходят до интерфейса

- **Владелец:** Андрей (контракт) + Оля (отображение)
- **Где:** ответ Backend по заданию, `frontend/src/api.ts`, экран результата.
- **Факт:** в E2E-06 Backend вернул `job.warnings: PROFILE_MISMATCH` («число педагогов отличается от профиля школы»), но `project` и UI этого не показывают: фронтенд читает только `variant.quality_report`.
- **Ожидаемо:** предупреждения задания либо попадают в проект и UI, либо явно не считаются пользовательскими.
- **Влияние:** пользователь не видит, что часть входных данных была скорректирована.
