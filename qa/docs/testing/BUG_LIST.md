## P1

### BUG-02. На `partial` не показаны причины отклонённых вариантов

- **Владелец:** Оля (отображение) + Андрей (контракт)
- **Где:** страница частичного результата, `frontend/src/api.ts`, ответ задания.
- **Факт:** API уже отдаёт `job.errors` и статусы вариантов. Но при `partial` интерфейс показывает только «Сценарии готовы частично» и готовые вкладки, без причин, почему остальные варианты не сформированы.
- **Ожидаемо:** на странице `partial` видно, какие варианты не готовы и почему.
- **Влияние:** педагог не понимает, чего не хватает; помочь может только поддержка.
- **Что уже сделано:** API-часть исправлена в PR #8 и проверена.

### BUG-03. Нет проверки внутреннего тайминга блока

- **Владелец:** Андрей (валидатор и текст сценария), проверка — Максим
- **Где:** `qa/docs/review/scenarios/labour_day_andrey.md`; проверки `check_grid`, `TIMING-*`.
- **Факт:** в блоке 45–55 минут пять команд выступают «до 3 минут» — это до 15 минут при бюджете 10. Сумма блоков ровно 60, поэтому автоматика пропускает сценарий.
- **Ожидаемо:** проверка бюджета действий внутри блока или обязательное замечание `high`.
- **Влияние:** педагог физически не успевает провести мероприятие.

## P2

### BUG-06. Формат issue не соответствует ТЗ 16.2

- **Владелец:** Андрей (сервис) + Максим (QA-модуль)
- **Где:** QA-модуль (`code / severity / message / field`), сервис (`code / severity / location / message`).
- **Факт:** в ТЗ есть `issue_id`, `category`, `repairable`, `suggested_action`.
- **Ожидаемо:** единый формат и маппинг.
- **Влияние:** два формата усложняют обработку замечаний.

### BUG-08. В форме нет ролей родителей

- **Владелец:** Оля (фронтенд)
- **Где:** `frontend/src/App.tsx`, блок «Участники и пространство».
- **Факт:** форма всегда отправляет `parent_roles=['audience']`. Нельзя выбрать `helper`, `active_participant`, `evaluator`, голосование или награду.
- **Ожидаемо:** роли и режим участия доступны, как в контракте 01.
- **Влияние:** сценарии с помощниками, жюри и голосованием недоступны через UI.

### BUG-09. Нет памятки для родителей

- **Владелец:** Андрей (генерация)
- **Где:** E2E-12, `womens_day`, 12 родителей, `audience_award`.
- **Факт:** `quality_report` выдаёт `PARENT-INSTRUCTION`: роли и голосование есть, памятки родителям нет.
- **Ожидаемо:** при включённых родителях есть памятка с обязанностями и границами участия.
- **Влияние:** родители приходят без инструкции, педагог объясняет всё сам.

### BUG-11. Даты рождества и Дня труда не зарегистрированы

- **Владелец:** Снежана (реестр источников) + Андрей (проверка)
- **Где:** E2E-13 `christmas`, E2E-16 `labour_day`.
- **Факт:** `quality_report` выдаёт `FACT-UNREGISTERED`: в сценарии есть дата, которой нет в реестре проверенных фактов.
- **Ожидаемо:** дата либо подтверждена источником, либо сценарий не утверждает её как факт.
- **Влияние:** педагог видит предупреждение; историческая точность не подтверждена.

## P3

### BUG-04. Fixture выбирает эталон не по событию

- **Владелец:** Андрей
- **Где:** `services/school_events_llm/app/llm/fixture.py`.
- **Факт:** HTTP-клиент берёт эталон по порядку, а не по `event_id`.
- **Обход:** `LLM_SERVICE_FIXTURES=<один golden>`.
- **Влияние:** только тестовая инфраструктура; реальная модель доступна.

### BUG-05. `SCRIPT-SHORT` требует калибровки

- **Владелец:** Андрей (порог), решение — Ярослав
- **Где:** `script_length.py`, `checks.py`.
- **Факт:** на 12 живых кейсах 0 замечаний, в UI-прогоне 1 (572 символа при пороге 700 для блока 15 минут). На fixture было по 2 в каждом сценарии.
- **Ожидаемо:** порог откалибровать под короткие блоки.
- **Влияние:** ложные предупреждения, если порог слишком строгий.

### BUG-07. Демо-каталог расходится с реальным

- **Владелец:** Оля
- **Где:** `frontend/src/api.ts`, `DEMO_EVENTS`.
- **Факт:** в демо 2 события и `teacher_day`; в реальном каталоге 14 событий и `teachers_day`.
- **Ожидаемо:** демо использует реальный каталог или явно помечено как учебное.
- **Влияние:** только демо-режим.

### BUG-10. `job.warnings` не доходят до UI

- **Владелец:** Андрей (контракт) + Оля (отображение)
- **Где:** ответ задания, экран результата.
- **Факт:** в E2E-06 Backend вернул `PROFILE_MISMATCH`, но UI показывает только `variant.quality_report`.
- **Ожидаемо:** предупреждения задания видны пользователю или явно не пользовательские.
- **Влияние:** пользователь не видит, что входные данные были скорректированы.
