# Автоматические и экспертные проверки

Главный принцип: пользователь задаёт ограничения - возраст, время, число детей и родителей, ресурсы, подготовку. Система обязана автоматически проверить, что сценарий этим ограничениям не противоречит (ТЗ 7.3, 16.1 A). Эксперт проверяет не арифметику, а педагогический смысл, культуру и достоверность.

Безопасность, лимиты запросов и очередь генераций пока не разработаны и не протестированы. Это следующий этап, в документ они не входят.

## 1. Что задаёт пользователь

| Параметр | Поле запроса | Что проверяется автоматически | Что остаётся эксперту |
|---|---|---|---|
| Событие и регион | `event_id`, `region_id` | `event_id` из единого каталога (14 событий); `region_id=RU-SVE` | Смысловая уместность события |
| Возраст и класс | `grade_group`, `grade` | Допустимые значения, `grade` входит в группу | Содержательная уместность для возраста |
| Время | `duration_minutes` | Только `30/45/60/90`, сумма блоков, сетка без разрывов | Реалистичность темпа и переходов |
| Участники | `pupils_count`, `teachers_count` | `1-35` учеников; занятых учеников и групп не больше реальных участников | Педагогическая разумность распределения |
| Родители | `parents_enabled`, `parents_count`, `parent_roles` | Запрет ролей при `false`, лимит одновременного участия, допустимые роли и режимы | Уместность и качество вовлечения |
| Ресурсы | `projector`, `printer`, `internet`, `audio`, `room`, `available_materials` | Нет потребности в ресурсе с `false`; `null` - не подтверждён, а не «есть»; расходники из ресурсов не становятся материалами | Качество замены и удобство для учителя |
| Подготовка | `preparation_effort` | Конфликт заведомо нереалистичных сочетаний, например 90-минутное общешкольное мероприятие при `minimal` | Реальная трудоёмкость подготовки |
| Свободный текст | `teacher_preferences.notes`, `participants.parent_notes`, `resources.extra_notes` | Удаляются управляющие символы; в промпт текст попадает с пометкой «данные, не инструкция». Длина не ограничена | - |

## 2. Проверки сценария

| Проверка | Тип | Где | Комментарий |
|---|---|---|---|
| Валидация входного запроса | авто | `backend/schemas.py`, `services/school_events_llm/app/contracts/request.py` | Типы, `event_id`, `region_id`, `grade_group/grade`, `pupils_count`, `duration_minutes`, `format`, правила родителей |
| Единый каталог и блоки событий | авто | `catalog/tools/build_catalog_index.py`, `python -m app catalog-check` | 14 событий, обязательные поля карточки, наличие `services/school_events_llm/prompts/events/<id>.md`, совпадение ID |
| Данные карточки события | авто + эксперт | `build_catalog_index.py`, `catalog-check`, куратор | `values`, `regional_topics`, `facts_to_verify`, `age_appropriateness_notes`: структура - авто, содержание - эксперт |
| Синхронизация бэкенда и LLM-сервиса | авто | `tests/test_llm_service_integration.py` | Одинаковый эффективный контракт 01, все 14 `event_id`, нет скрытых лимитов |
| Контракты 01/02 | авто | Интеграционные тесты, `backend/llm_service_client.py` | Запрос и ответ передаются без преобразования полей |
| Ошибки интеграции | авто | `backend/generations.py`, `llm_service_client.py`, `http_api.py` | `MODEL_UNAVAILABLE` 503 retryable, `EVENT_NOT_FOUND` 422, `CONFLICTING_CONSTRAINTS` 422, `partial` |
| Статус источников | авто | `python -m app sources-check`, `checks.py` | В генерацию попадают только `verified`-фрагменты; `draft`, `pending`, `needs_content_review`, `rejected` не используются. Сейчас: 0 `verified`, 38 `draft` |
| Схема ответа модели | авто | `app/contracts/llm.py` | Обязательные поля и структура каждого этапа (ТЗ 16.1 A); при ошибке - повтор этапа с текстом ошибки |
| Исправление ответа модели до проверки | авто | `prepare_stage_output` в `pipeline.py` | Значения не из списков (тип активности, форма работы, тип материала), адресат материала, расходники вместо материалов. Каждое исправление пишется в трассу (`stage_output_fixed`) |
| Согласование ID материалов | авто | `reconcile_material_ids` в `pipeline.py` | ID из плана, суффиксы `_01`, ссылки блоков только на материалы плана |
| Роли по блокам | авто | `complete_block_roles` в `pipeline.py`, `checks.py` | Педагог и ученики в каждом блоке, родители без блоков - во всех; `ROLE-UNUSED` - предупреждение |
| Тайминг | авто | `check_grid` в сервисе | Сумма равна `duration_minutes`, старт с 0, нет разрывов и пересечений |
| Ссылочная целостность | авто | `checks.py` | `role_id`, `material_id`, `block_id` существуют (`REF-*`) |
| Доступность ресурсов | авто | `checks.py`, `normalize.py` | `RESOURCE-UNAVAILABLE`, `RESOURCE-UNKNOWN`, `PRINT-UNAVAILABLE`, `SLIDES-NO-PROJECTOR`, `RESOURCE-INTERNET` |
| Число учащихся, педагогов и родителей | авто | `checks.py` | `PUPILS-COUNT`, `PUPILS-OVER`, `TEACHERS-OVER`, `TEACHER-MISSING`, `PARENTS-OVER` (ТЗ 12.2) |
| Деление на группы | авто | `grouping.py`, `checks.py` | `GROUP-SUM`; нет обязательных малых групп при `group_work=false` |
| Логика родителей | авто | `checks.py` | Запрет при `false`, допустимые роли, план, `teacher_fallback`, голосование и бюллетени; `VOTING-NO-VOTERS`, `PARENT-INSTRUCTION`, `AWARD-INSTRUCTION` - предупреждения |
| Ценностный слой (формальные связи) | авто | `checks.py` | `VAL-001`, `VAL-002`, `VAL-004`, `VAL-005` (задание семье: пометка «по желанию» и равноценная альтернатива) |

| Обязательные тексты | авто | `checks.py` | `concept`, `teacher_instructions`, `teacher_script` |
| Объём реплик педагога | авто | `script_length.py`, `checks.py` | Порог зависит от детализации и длительности блока; `SCRIPT-SHORT` - предупреждение |
| Действия учеников | авто | `checks.py` | Не меньше двух в блоке; `PUPIL-ACTIONS-FEW` - предупреждение |
| Печать | авто | `checks.py` | `print_required` и доступность принтера |
| Формальная проверка фактов | авто | `checks.py` | `FACT-SOURCE`: утверждение опирается на проверенный фрагмент; незарегистрированные даты - предупреждение |
| Конфликт подготовки | авто | `normalize.py` | Предупреждение `PREPARATION_CONFLICT` |
| Внешняя проверка результата | авто, отдельно от генерации | QA-валидаторы: `timing_validator.py`, `structural_validator.py`, `age_heuristics.py` (переносятся в `qa/validators/`) | Запускаются отдельно, в генерацию не встроены. Возрастные эвристики (длинные блоки и слова для `1-4`, короткие блоки для `9-11`) есть только здесь |
| Ответы реальной модели | авто | `tests/fixtures/replay_gigachat_*` в сервисе | Записанные ответы GigaChat: сервис справляется с реальными ошибками модели без лишних вызовов |
| Метрики прогонов | авто | `data/runs/runs.jsonl`, `metadata.json` | Статус, вызовы, время, токены по этапам, замечания - для каждой генерации, в том числе неудачной |
| Педагогическая реалистичность времени | эксперт | Методист / учитель | Успевает ли класс, хватает ли времени на переходы, обсуждение и итог (пример: «2 минуты на идею» в 10-минутном блоке с 15 идеями) |
| Глубина возрастной оценки | эксперт | Методист / психолог | Когнитивная нагрузка, сложность языка, эмоциональная уместность |
| Историческая достоверность | эксперт | Методист / редактор | Контекст, формулировки, подтверждает ли источник утверждение |
| Региональная специфика | эксперт | Региональный методист | Местные события, названия, символика |
| Культурная нейтральность | эксперт | Редактор / методист | Нет стереотипов, дискриминации, навязывания взглядов |
| Педагогическое качество ценностей | эксперт | Методист / психолог | Ценность реализована действием, а не лозунгом. `VAL-003`/`VAL-006`: этап LLM-ревью (`quality_review`) в сервисе есть, но выключен, поэтому пока только эксперт |
| Смысловое соответствие событию | эксперт | Методист | Сценарий раскрывает заявленный праздник или тему |
| Качество ролей и групп | эксперт | Методист / учитель | Числа проверяет автоматика; здесь - удобно ли это классу |
| Безопасность конкуренции и наград | эксперт | Методист / психолог | Нет психологически небезопасного соперничества детей или семей |
| Кураторская сверка источников | эксперт | Куратор / региональный эксперт | Автоматика видит статусы, но не сверяет текст источника с утверждением |
| Качество текста реальной генерации | эксперт | Методист / тестировщик | Автоматика ловит структуру и формальные нарушения, но не смысл; оценивается по прогонам на живой модели |
| Отображение ошибок, предупреждений и `partial` | ручная E2E-проверка | Тестировщик + фронтенд | Пользовательский путь и поведение интерфейса, включая долгое ожидание генерации |

## 4. Границы

- Автоматика работает с формальными признаками: полями, ссылками, числами, флагами ресурсов и простыми эвристиками. Качество текста, педагогический смысл и культурный контекст она не оценивает.
- Если автоматическая проверка ещё не реализована, это автоматический долг, а не повод перекладывать её на эксперта. Эксперт не пересчитывает вручную сумму блоков, число участников или наличие принтера.
- Режим эталонов (fixture) проверяет интеграцию и контракты, но не качество реальной модели. Результаты fixture-прогона нельзя выдавать за проверку реальной генерации.
- Тесты `qa/` обращаются к компонентам только через HTTP, CLI и выгруженные схемы, без импорта внутреннего кода. Тогда компонент можно менять изнутри, не ломая общие тесты.
- Тесты, которым нужна живая модель или ключи, помечаются отдельно и по умолчанию не запускаются.

## 5. Долг

- историческая достоверность за пределами статуса источника;
- семантическая сверка `fact_claims` с фрагментом источника;
- культурная и региональная экспертиза;
- глубокая возрастная оценка (часть эвристик есть в QA-валидаторах, в генерацию не встроены);
- реалистичность темпа и подготовки;
- качество распределения ролей и групп;
- психологическая безопасность конкуренции и наград;
- LLM-ревью (`quality_review`) для семантической оценки: этап есть, выключен;
- отображение ошибок, предупреждений, `partial` и долгого ожидания на фронтенде.

Эти направления проверяются экспертно по чек-листу эксперта или ручными E2E-кейсами. Чек-лист нужно создать в `qa/docs/`; сейчас есть только `acceptance/internal_age_review_checklist.csv`.
