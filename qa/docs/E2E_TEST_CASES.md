# E2E-тест-кейсы приложения

Набор пользовательских сценариев для проверки единого приложения: фронтенд → основной Backend → LLM-сервис → модель или fixture. Основной режим проверки — API-режим, а не демонстрационный mock.

Перед прогоном:

```bash
# LLM-сервис
cd services/school_events_llm
python -m app serve

# Backend в другом окне
$env:GENERATOR_MODE="llm_service"
python -m uvicorn backend.main:app --reload --port 8000
```

Если реальная модель недоступна, допускается `LLM_SERVICE_FIXTURE_MODE=true` с эталонными ответами. Это проверка интеграции, но не проверка качества реальной генерации.

Ограничение fixture-режима: в HTTP-режиме эталон выбирается по порядку, а не по `event_id`, поэтому без реальной модели проходят только запросы, совпадающие с первым эталоном (`knowledge_day`). Для остальных событий нужен реальный провайдер или исправление fixture-клиента (BUG-04 в `BUG_LIST.md`).

Каталог проверяется через `GET /api/v1/catalog/events`: должно быть 14 событий, без `ural_culture`.

Перед прогоном также проверьте каталог и источники:

```bash
python catalog/tools/build_catalog_index.py --check
cd services/school_events_llm
python -m app catalog-check
python -m app sources-check
```

## E2E-01. Базовый классный час без родителей

- **Вход:** `teachers_day`, `grade_group=5-8`, 22 ученика, 45 минут, `class_hour`, родители выключены, 1 вариант.
- **Ожидаем:** HTTP 202 и `project.status=completed`; сумма блоков 45; минимум 3 блока; у каждого есть `teacher_script`; есть `teacher_instructions`; нет родительских ролей и плана; нет `critical` и `high`.
- **Примечания:** fixture `05_no_parents.json`. Проверить, что сценарий не выглядит пустым без родителей.

## E2E-02. Короткий классный час для начальной школы

## E2E-10. Ошибка LLM-сервиса и ошибки каталога

- **Вход:** `knowledge_day`, `grade_group=5-8`, 22 ученика, 45 минут, `class_hour`; Backend запущен с `GENERATOR_MODE=llm_service`, LLM-сервис остановлен.
- **Ожидаем:** HTTP 503, `code=MODEL_UNAVAILABLE`, `retryable=true`; нет тихого переключения на mock; проект не создаётся; интерфейс показывает ошибку и предлагает повторить.
- **Дополнительно:** `event_id=ural_culture` → 422 `EVENT_NOT_FOUND`; неподдерживаемые возраст или формат → 422 `CONFLICTING_CONSTRAINTS`; неверный `SERVICE_AUTH_TOKEN` → 401 `SERVICE_UNAUTHORIZED`; неизвестный `GENERATOR_MODE` → 500 `INTERNAL_ERROR`.
- **Примечания:** негативный кейс. Проверяется именно API-режим; mock не должен маскировать недоступность сервиса.

## E2E-12. Полный happy path с несколькими вариантами

- **Вход:** `knowledge_day`, `grade_group=5-8`, 6 класс, 27 учеников, 45 минут, `class_hour`, родители включены, `parents_count=12`, `helper` и `audience`, проектор и принтер доступны, `audience_award`, 3 варианта.
- **Ожидаем:** HTTP 202; при трёх готовых вариантах `project.status=completed` и 3 различных варианта; при меньшем числе — `partial`, фронт показывает доступные варианты и предупреждение. Нет `critical` и `high`; сумма блоков 45; все ссылки валидны; план родителей включён; материалы с печатью имеют `printer` в зависимостях или доступный принтер; возрастных предупреждений нет.
- **Примечания:** fixture `01_happy_path_45min.json`; `variants_count` увеличен до 3. Если fixture-режим возвращает один вариант, это ожидаемый `partial`, а не `completed`. Отдельно проверить, что интерфейс показывает готовый вариант и предупреждение, а не таймаут (BUG-01).

## Как использовать

1. Запустить LLM-сервис и Backend в API-режиме (`GENERATOR_MODE=llm_service`).
2. Прогнать каждый кейс через пользовательский путь: выбор события → параметры → генерация → проект.
3. Проверить HTTP-коды, `job.status`, `project.status`, `completed_variants`.
4. Проверить `quality_report`: отсутствие `critical`, наличие ожидаемых предупреждений.
5. Проверить автоматические ограничения: сумму времени, ресурсы, число учащихся/педагогов/родителей, сумму групп.
6. Проверить отображение ошибок, предупреждений, нескольких вариантов и `partial`.
7. Для содержательных вопросов пройти `CONTENT_REVIEW_CHECKLIST.md`.
8. Отдельно проверить долгое ожидание: индикатор прогресса, отсутствие «зависшего» экрана и понятное сообщение при `partial` и `failed`.
